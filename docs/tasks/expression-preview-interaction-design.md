# 表达式预览与应用交互设计

状态：已选择方案 A。本文不表示功能已实现。

实施规划：[unify-expression-preview-interaction](../../openspec/changes/unify-expression-preview-interaction/proposal.md)。该 change 覆盖 Avalonia 与 Web。

适用端：Avalonia 桌面端与 Blazor WebAssembly Web 端。
目标：用户可以看清表达式将修改什么，再一次性应用。一次撤销恢复整次应用。
推荐：方案 A「独立弹窗 + 章节前后对照」。窄屏使用同一信息结构的纵向条目。

## 1. 设计依据与现状

本文承接 [统一编辑模型与历史方案](unified-editing-and-unbounded-history.md) 的事务语义。
Web 容器沿用 [弹窗布局方案](wasm-modal-layout-and-regression-plan.md) 的单弹窗、焦点与关闭规则。
本文细化表达式任务内部的信息结构和确认行为。
本文保留方案比较。后续实施以选定方案 A 和对应 OpenSpec change 为准。

截图中的预览存在以下问题。

| 问题 | 用户受到的影响 | 设计要求 |
| --- | --- | --- |
| 一个章节拆成多个项目符号 | 无法连续比较同一章节的前后值 | 按章节聚合 |
| `FrameAccuracy`、`Neutral`、对象字符串直接显示 | 需要理解内部数据结构 | 使用本地化业务名称和值 |
| 修改前显示为空字符串 | 无法区分未知、未计算和零 | 明确显示缺失状态 |
| 帧数、时间与帧率混排 | 难以看出真正的时间变化 | 时间为主，帧信息为辅，公共属性单独列出 |
| 多行脚本挤在单行输入框 | 难以检查脚本 | 保留多行、缩进与可扩展编辑区域 |
| 缺少范围和影响数量 | 无法判断将修改哪些章节 | 在预览顶部固定显示范围与摘要 |

以下结论来自当前源码，不从截图推断具体计算结果。

- Avalonia 使用 `ExpressionToolViewModel.BuildPreviewSummary` 拼接差异文本。它只取前 8 条。
- Avalonia 的预览区域使用 `TextBlock`，最大高度为 180。
- Avalonia 的应用路径先调用 `RefreshPreviewNow`。它会重新计算候选。
- Web 的 `ExpressionDialog.razor` 使用单行输入与差异列表。
- Web 的 `FormatExpressionDifference` 只对时间和帧数做专用处理。其他字段回退到内部字段名与字符串。
- Web 当前以所选轨道准备表达式候选。缺少帧率时，准备路径可能把检测帧率写入候选。
- Web 应用路径检查候选基准。基准过期时，它重新准备预览并返回失败，不直接提交新结果。
- Core 的 `ChapterContentPreview` 已包含修改前快照、候选快照、目标身份和版本基准。
- Core 的应用入口可以直接提交候选。展示前后对照不需要把预览写入主文档。

因此，截图中出现帧数变化，不足以证明章节时间发生变化。
设计必须区分「时间变化」「帧信息更新」和「公共属性变化」。

## 2. 三个可选方案

三种方案共用同一套计算、确认、取消和撤销规则。
它们只改变结果的呈现位置和浏览方式。

| 方案 | 布局 | 优点 | 代价 | 适合场景 |
| --- | --- | --- | --- | --- |
| A，推荐 | 独立弹窗。上方编辑，下方章节前后对照 | 原值与结果同时可见。流程短。两端容易统一 | 长脚本与长表格需要分配高度 | 日常偏移、修正与批量表达式 |
| B | 独立工作区。左侧脚本，右侧完整候选章节表 | 可以查看结果表的整体形态。适合复杂脚本 | 前后值需要切换或打开行详情。宽度要求更高 | 长时间调试、多行脚本 |
| C | 两步弹窗。「编辑表达式」→「检查并应用」 | 每一步内容少。手机确认更集中 | 输入时不能持续看到完整结果。往返次数更多 | 偶尔使用、重视分步确认 |

### 2.1 方案 A：编辑与对照同屏

```text
时间表达式                                            ×
范围：当前轨道「正片」· 12 个章节

预设 [自定义                  ▾]        [导入脚本]
表达式                                              [展开]
┌──────────────────────────────────────────────────────┐
│ t + 5                                                │
└──────────────────────────────────────────────────────┘
输入后自动更新预览。应用前，章节内容保持不变。

预览已更新 · 12 个章节时间变化 · 0 个未变化
显示 [仅变化 ▾]                          [时间 / 帧数]
章节             修改前          应用后          变化量
01 片头          00:00:00.000    00:00:05.000    +5.000 秒
02 正片          00:01:00.000    00:01:05.000    +5.000 秒
03 片尾          00:02:00.000    00:02:05.000    +5.000 秒
…其余章节可滚动查看

应用后可一次撤销。                    [取消] [应用更改]
```

上图使用 `t + 5` 的示例数据。它不代表截图中脚本的实际输出。
应用后的时间必须来自候选快照。
界面不得根据脚本文本猜测预览值。

### 2.2 方案 B：完整候选表为主

```text
时间表达式                                            ×
范围：当前轨道「正片」· 12 个章节
┌──────────────────┬───────────────────────────────────┐
│ 预设与脚本       │ 结果视图 [应用后] [修改前]          │
│                  │ 章节       时间            名称   │
│ t + 5            │ 01 已修改  00:00:05.000    片头   │
│                  │ 02 已修改  00:01:05.000    正片   │
│                  │ 选中章节：原值 → 结果；变化量     │
└──────────────────┴───────────────────────────────────┘
12 个章节时间变化。                   [取消] [应用更改]
```

候选表只读。标题始终显示「应用后预览，尚未应用」。
切换前后视图时，保留滚动位置和选中章节。
主窗口中的章节表仍显示已提交文档。
窄屏必须改为上下布局，不能压缩两栏。

本方案适合完整浏览结果，但同屏对照能力弱于 A。
若选择本方案，需要为每个变化行提供可展开的前后详情。

### 2.3 方案 C：分步检查

```text
步骤 1：编辑表达式
预设 + 多行编辑器 + 实时摘要 / 错误
3 个章节时间变化。                [取消] [检查结果 →]

步骤 2：检查并应用
范围 + 与方案 A 相同的前后对照 + 公共属性变化
                         [返回编辑] [取消] [应用更改]
```

步骤 1 的摘要随输入更新。
步骤 2 展示完整候选，不重新执行已完成的同一轮计算。
返回编辑后，只有实际修改参数才使候选失效。
步骤 2 仍需处理文档版本过期。

## 3. 推荐方案 A 的统一信息结构

### 3.1 标题、范围与脚本

- 标题统一为「时间表达式」。入口统一为「表达式…」。
- 范围显示真实轨道名称和参与计算的章节数。
- 第一阶段沿用当前轨道范围。不新增选中章节或全部轨道选择器。
- 若存在分隔行，摘要另写「另有 2 个分隔行，不参与计算」。
- 预设选择器显示名称。选中后在下方显示简短说明。
- 修改预设脚本后，名称改为「自定义」。
- 编辑器保留换行和缩进。多行预设不得压成单行。
- 默认显示约 4–6 行。用户可以展开编辑区域。
- 简短表达式可以使用较少高度。不得挤占全部结果空间。
- 两端均提供多行文本编辑。补全和语法着色可以保留宿主差异。
- 导入脚本按宿主能力显示。未提供文件能力时不显示空按钮。

统一的是任务顺序、术语和确认语义。
两端不需要复制相同的原生控件外观。

### 3.2 摘要先回答「改了什么」

推荐摘要：

> 12 个章节中，3 个时间变化，9 个时间未变化。

存在额外影响时，增加一行：

> 另有 12 个章节的帧信息更新；帧率：未设置 → 24 fps。

「时间变化」和「帧信息更新」可以包含同一章节。
界面不得将两项数量相加后称为受影响章节总数。
受影响章节总数必须按章节身份去重。
轨道或文档属性变化必须单独计数。

如果只有帧信息变化，摘要使用：

> 章节时间未变化。3 个章节的帧信息将更新。

如果只有公共属性变化，摘要使用：

> 章节时间未变化。帧率将从未设置变为 24 fps。

如果整个候选与基准相同，显示「没有可应用的更改」，禁用应用。
不能只根据时间变化数量判断是否允许应用。
也不能将帧信息变化伪装成时间变化。

### 3.3 章节对照表

默认列为「章节」「修改前」「应用后」「变化量」。
默认单位为时间。用户可以切换到帧数。
两种视图使用相同的章节顺序和过滤条件。

| 元素 | 规则 |
| --- | --- |
| 章节身份 | 显示编号与名称。内部使用稳定章节身份匹配 |
| 行顺序 | 保持当前轨道顺序。不按差值自动排序 |
| 修改前 | 来自本轮计算基准 |
| 应用后 | 来自本轮候选 |
| 时间变化量 | 显示正负号和单位。例如 `+5.000 秒`、`−0.125 秒`、`未变化` |
| 默认过滤 | 仅变化。包含时间变化与仅帧信息变化的章节 |
| 可选过滤 | 全部章节。用于核对相邻章节与上下文 |
| 默认标识 | 时间变化显示「时间已修改」。仅帧信息变化显示「帧信息更新」 |
| 行详情 | 展开显示帧数前后值、帧对齐状态，以及其他实际变化字段 |
| 长名称 | 允许换行或展开查看完整名称。不能只靠鼠标悬停 |
| 大量章节 | 使用虚拟化或分页。显示总数。所有变化都必须可访问 |

表格不是另一份编辑表。
预览行不能改值、删除或单独勾选应用。
首版不提供逐行排除。这样可以保持表达式整体计算与原子提交的语义。
过滤仅影响显示，不影响本次提交范围。

### 3.4 时间、帧与公共属性格式

时间默认显示 `HH:mm:ss.fff`，与主表格的时间表达保持一致。
如果真实差异小于显示精度，增加必要的小数位。
不得让有变化的行显示两个相同时间和零差值。

帧数必须标出使用的帧率。
前后帧率不同时，分别显示两侧帧率。
这时不直接显示一个可能误导的帧差值。
帧率未知时，显示「无法计算：帧率未设置」。
原帧信息为空时，显示「未计算」，不得显示空白或零。
只有在业务语义已确认后，才能将 `Neutral` 映射为「未评估」等用户文案。
`Accurate` 与 `Inexact` 的文案必须根据现有容差定义校核。
可以使用「对齐到帧」「未对齐到帧」等说明，但不能把容差判断误写为绝对数学结论。

公共属性放在摘要下方的独立区域。
例如：

| 属性 | 修改前 | 应用后 |
| --- | --- | --- |
| 帧率 | 未设置 | 24 fps |

分数帧率可以显示 `23.976 fps（24000/1001）`。
不能显示 `ChapterFrameRate { Numerator = … }`。
候选若修改了时间以外的持久字段，界面必须明确呈现。
不改变 Core 对帧信息的当前存储约定，也不在本设计中顺带重构编辑模型。

### 3.5 窄屏呈现

窄屏仍使用方案 A，不增加另一套确认流程。
每个章节转换为一个纵向条目。

```text
时间表达式                           ×
当前轨道「正片」· 12 个章节
预设 [自定义                        ▾]
表达式
┌────────────────────────────────────┐
│ t + 5                              │
└────────────────────────────────────┘
预览已更新 · 3 个章节时间变化
显示 [仅变化 ▾]       单位 [时间 ▾]

02 正片                  时间已修改
修改前    00:01:00.000
应用后    00:01:05.000
变化量    +5.000 秒
[帧信息详情 ▾]

03 片尾                  时间已修改
修改前    00:02:00.000
应用后    00:02:05.000
变化量    +5.000 秒

可一次撤销。       [取消] [应用更改]
```

以内容是否容纳作为切换依据。
建议在约 720 CSS px / DIP 以下使用纵向条目，最终以本地化长文本实测调整。
桌面端允许缩放工具窗口。Web 手机端使用接近全屏的弹窗。
标题与底部按钮必须保持可访问。
Web 优先让内容区统一滚动，避免短视口出现多层结果滚动。
宽桌面可以为编辑器和结果分别分配滚动区域。
移动键盘出现后，当前输入与关闭入口必须可见。
应用按钮不得被键盘或安全区域永久遮挡。
触控操作目标以至少 44×44 CSS px 为设计目标。

## 4. 统一的状态与按钮行为

页脚固定显示次要按钮「取消」和主要按钮「应用更改」。
按钮不得随计算状态出现或消失。
禁止自动将焦点移动到应用按钮。

| 状态 | 结果区域 | 应用按钮 | 用户下一步 |
| --- | --- | --- | --- |
| 没有文档或没有可计算章节 | 显示原因 | 禁用 | 关闭并加载章节 |
| 表达式为空 | 「请输入表达式或选择预设」 | 禁用 | 输入或选择预设 |
| 输入后等待更新 | 「等待更新预览…」 | 禁用 | 继续输入或等待 |
| 正在计算 | 「正在计算预览…」 | 禁用 | 等待或取消 |
| 成功且有变化 | 摘要与完整对照 | 启用 | 检查后应用 |
| 成功且无变化 | 「没有可应用的更改」 | 禁用 | 修改表达式或取消 |
| 语法或运行错误 | 就近错误与失败摘要 | 禁用 | 修正表达式 |
| 文档基准过期 | 「章节已变化，请更新预览」 | 禁用 | 点击「更新预览」后重新检查 |
| 正在应用 | 保留已确认的结果，显示「正在应用…」 | 禁用 | 等待完成 |
| 应用失败 | 明确原因，保留草稿 | 依原因决定 | 修正或重试 |
| 应用成功 | 关闭工具，回到章节表 | 不适用 | 继续编辑或撤销 |

输入立即使旧候选失去可提交资格。
推荐两端统一使用约 250 ms 防抖。
输入法组合期间不启动计算。
防抖时间属于体验参数，可以根据实际耗时调整。
旧预览可以暂时保留以避免布局跳动，但必须标记「旧预览，等待更新」。
旧预览不能保持可应用状态。
快速输入时，只接受最新一轮结果。
关闭工具后，迟到的结果不得恢复工具或更新当前文档。

有一行失败时，整次表达式不能应用。
显示示例：「无法应用：第 8 章产生负时间。章节内容未修改。」
可定位的错误应链接到对应章节或脚本行。
如果当前诊断没有位置，显示明确原因，不猜测行号。
不得将部分成功行呈现为完整有效候选。
警告与阻断错误使用不同标识。
颜色必须配合文字或图标。

空表达式禁用是本方案建议的产品规则。
它与 Web 当前将空白表达式解释为 `t` 的行为不同。
显式输入 `t` 时，仍以完整候选判断是否存在帧信息或公共属性变化。

## 5. 确认、原子提交与撤销

### 5.1 应用用户已检查的那一份结果

应用资格同时要求以下条件。

1. 预览计算成功。
2. 存在实际可提交变化。
3. 草稿与本轮预览参数相同。
4. 目标章节与范围没有变化。
5. 当前文档基准与预览基准相同。
6. 当前没有提交进行中。

点击应用后，直接提交已展示的候选。
应用处理不得先重算，再无提示地提交另一份候选。
如必须重算，则显示新预览，等待用户再次点击应用。
重新计算不能沿用先前的确认。
预览过期时，不自动关闭弹窗。
两端统一提供「更新预览」操作，并保留脚本。

双击、触控重复事件与请求重试只能产生一次事务。
按钮禁用负责防误触，提交身份负责防重复提交。
提交成功之前不得清空错误恢复所需的草稿与预览。

### 5.2 应用之后

应用成功后，两端都关闭表达式工具。
主表格显示已提交结果，并保持原来的滚动位置与选中章节。
状态栏显示「已应用表达式：3 个章节时间变化。可撤销」。
如果只有帧信息或公共属性变化，状态栏使用对应摘要。
历史显示一条表达式应用记录。
点击主界面的撤销，必须一次恢复本次全部变化。
重做恢复同一结果，不重新执行脚本。

应用成功后可以保存表达式参数，便于下次使用。
保存参数不表示表达式持续生效。
再次打开工具时，从当前已提交文档准备新预览。
再次应用属于另一次显式编辑。
例如，连续两次应用 `t + 5` 会累计移动 10 秒，并产生两条历史记录。

### 5.3 取消与关闭

取消、关闭按钮和 Escape 使用同一条丢弃路径。
它们丢弃本次候选，并恢复进入工具前的参数基准。
它们不修改文档，也不增加历史记录。
点击遮罩不关闭表达式工具，避免误触丢失脚本。
首次方案不增加二次取消确认弹窗。

提交前可以取消计算并关闭。
短暂的提交阶段禁用关闭和取消，等待确定结果。
提交结果确定后恢复相应操作。
不要用「取消」承诺回滚一个可能已经完成的提交。

脚本编辑器中的 Ctrl/Cmd+Z 只撤销脚本文本输入。
表达式工具打开期间，不从模态背景触发文档撤销。
关闭工具后，主界面撤销操作恢复文档事务。
Enter 在多行编辑器中换行，不触发应用。
首版不新增全局应用快捷键。
Escape 应先关闭补全列表等内部临时界面，再由外层工具处理关闭。

## 6. 两端一致性与实现边界

| 项目 | 两端必须一致 | 宿主可以不同 |
| --- | --- | --- |
| 信息 | 范围、摘要、前后值、单位、缺失值、错误 | 字体与原生控件外观 |
| 流程 | 编辑 → 自动预览 → 显式应用 → 返回主表格 | 桌面工具窗口与 Web 弹窗容器 |
| 确认 | 提交已展示的候选，过期后重新检查 | 调度与渲染机制 |
| 关闭 | 取消、关闭与 Escape 语义相同 | 系统窗口关闭事件与浏览器焦点管理 |
| 可访问性 | 有标签、键盘可达、变化不只靠颜色 | Avalonia 自动化属性与 Web ARIA |
| 本地化 | 共用术语、数量模板和单位 | 本地化资源加载方式 |

Web 状态通知使用温和播报。
不要在每次按键后播报整个表格。
计算完成只播报摘要，错误出现时播报原因。
关闭后焦点返回表达式入口。
切换单位或过滤条件不得抢走编辑焦点。

实现时从 `Before` 与 `Candidate` 生成结构化展示数据。
不要解析 `Differences.Before/After` 中的对象字符串来恢复时间或帧率。
展示层必须保留所有实际变化的可见入口。
新增未知变化字段时，不得静默遗漏。
字段格式化与数量统计应在两端共用的宿主无关层实现。
具体归属在实施时根据依赖方向决定，不让 Core 引用 UI 控件。

## 7. 实施后的验收场景

下表是后续实施验收要求，不是本次文档已执行的测试。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 3 个章节应用 `t + 5` | 原值、结果和 `+5.000 秒` 同时可见 |
| 截图所示的仅帧信息变化 | 明确说明时间未变。无内部字段名和对象字符串 |
| 未知帧率或原帧值为空 | 分别显示未设置、未计算。不能冒充零 |
| 小于 1 ms 的真实变化 | 能识别前后不同。差值不能被显示为零 |
| 无变化 | 两端都禁用应用。历史不增加 |
| 仅公共属性变化 | 属性前后值可见。允许将有效变化一次提交 |
| 第 8 章计算失败 | 应用禁用。前 7 章也不提交 |
| 快速修改和输入法组合 | 无旧结果覆盖新结果，无未完成输入提交 |
| 预览之后文档版本改变 | 应用禁用或提交被拒绝。更新后再次确认 |
| 预览之后草稿改变 | 旧候选立即不可应用 |
| 双击应用 | 文档只改变一次，历史只增加一次 |
| 取消、Escape、关闭 | 文档与历史保持不变，参数恢复打开前基准 |
| 应用后撤销与重做 | 一次恢复全部变化。重做不重跑表达式 |
| 1000 个章节 | 所有差异可访问，计数完整，不限于前 8 条 |
| 长脚本、长名称和长错误 | 内容可读，按钮不被推出可访问区域 |
| 仅键盘、屏幕阅读器 | 能找到范围、结果、错误和应用；关闭后焦点恢复 |
