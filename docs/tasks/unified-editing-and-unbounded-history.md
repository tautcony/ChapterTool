# ChapterTool 统一编辑模型与不限步数历史方案

状态：实施方案。实现范围与验收要求由本文完整定义。

设计决策：采用唯一当前文档、不可变状态、内存历史树和统一事务入口。
本文中的“反撤销”统一称为“重做”。
撤销和重做恢复已提交状态，不重新执行业务操作。

## 1. 目标与核心决策

本方案替代此前“原始章节编辑 + 持续输出投影”的方案。

ChapterTool 只保留一份当前可编辑文档。
所有编辑操作都修改这份文档。
表格、格式预览和导出都读取这份文档。
模板和表达式是一次性编辑操作。
它们不是保存时再次执行的输出规则。

历史不设置操作条数上限。
文档会话内的全部已提交历史保留在内存中。
撤销后产生新编辑时，旧分支仍保留。
重做可以恢复当前分支，也可以选择其他已保留分支。
关闭或替换文档会话时释放其历史。
应用退出、进程崩溃或浏览器页面刷新后，历史不保留。
本功能不增加历史持久化、自动恢复或历史包导入导出能力。

本方案中的 `must` 表示要求。
`may` 表示许可。
`can` 表示能力。

“不限步数”表示产品不主动截断已提交历史。
它不表示设备具有无限内存。
历史占用随编辑内容和分支数量增长。
实现 must 不按条数、时间或内存阈值自动删除历史。
可检测且可恢复的内存分配失败 must 拒绝本次操作，并保留原会话状态。
操作系统终止进程或运行时无法恢复的内存耗尽不在可恢复保证内。
界面 must 明确说明历史仅在当前文档会话中有效。

## 3. 唯一文档状态

### 3.1 概念结构

以下结构用于描述所有权。
它不要求立即替换全部公共 Core 数据类型。
`Workspace` 的当前文档、状态身份、修改版本和游标由同一个 `SessionState` 提供。
这些属性是只读访问入口，must 不保存可分别修改的副本。

```text
Workspace
  DocumentId
  CurrentDocument
  CurrentStateId
  MutationRevision
  HistoryCursor
  ViewState
  ActiveDraft
  ExportPreferences

ChapterDocument
  DocumentMetadata
  OrderedTracks

ChapterTrack
  TrackId
  Metadata
  DurationTicks?
  EffectiveFrameRate?
  NumberingPolicy
  OrderedChapters
  SegmentBoundaries

EditableChapter
  ChapterId
  Name
  StartTicks
  EndTicks?
  Kind
  Provenance?
```

`CurrentDocument` 是唯一权威的当前章节状态。
已发布的文档及其集合 must 不可变。
编辑通过替换整个状态引用生效。
宿主 must 不获得可修改内部集合的引用。
候选、导出快照和历史记录 can 共享不可变数据。
这些快照不是另一份可独立提交的工作文档。
`ChapterSet` can 作为现有纯业务服务的输入和输出契约。
适配器 must 从当前文档生成 `ChapterSet`。
适配器 must 将服务结果转换为一个候选状态。
适配器 must 不长期保留第二份可编辑 `ChapterSet`。

导入原稿属于历史根节点。
原稿不是与当前文档并行运行的编辑缓冲区。
撤销到根节点可以恢复原稿。
当前文档 can 保存源路径、媒体引用和导入格式。
这些来源信息不具有另一份可编辑章节集合。

### 3.2 时间、帧率与编号

时间以有符号 64 位整数 ticks 保存。
一个 tick 等于 100 ns，与 `TimeSpan` 一致。
显示文本不是时间的权威值。
已知帧率以约分后的正有理数保存。
未知帧率使用空值，must 不用零参与计算。
帧与 ticks 转换 must 使用统一舍入规则：取最近整数，中点远离零。
计算 must 检测中间值和最终值的溢出。
浮点兼容输入 must 在适配边界转换一次。
实现 must 不因浮点显示误差产生新编辑。

未知总时长使用空值，must 不与真实零时长混用。
只有已知总时长才执行章节时间上界校验。
依赖总时长的合并和按边界拆分 must 要求明确时长。
适配旧 `ChapterSet.Duration` 时，must 按导入格式区分未知时长与零时长。
实现 must 不把最后一个章节起点自动当作媒体终点。

章节顺序由 `OrderedChapters` 决定。
编号起点属于 `NumberingPolicy`。
显示编号由章节顺序和编号起点推导。
修改编号起点是一条文档事务。
派生编号不另存为可独立修改的状态。

有效帧率属于轨道内容。
帧显示精度和准确度容差属于视图或应用偏好。
帧文本和准确度标记在刷新时计算。
显示刷新 must 不修改有效帧率或章节时间。

### 3.3 稳定身份

| 标识 | 规则 |
| --- | --- |
| `DocumentId` | 标识当前文档会话及其内存历史 |
| `TrackId` | 标识当前可编辑章节轨道 |
| `ChapterId` | 修改名称、时间或位置时保持不变 |
| `StateId` | 标识一个已提交的历史状态 |
| `TransactionId` | 标识一次操作；用于重试去重 |
| `MutationRevision` | 每次成功编辑、撤销、重做或分支切换后递增 |

新增章节在候选计算时分配身份。
重做 must 复用首次提交的身份。
删除后撤销 must 恢复原身份。
合并和拆分 must 保持已有章节身份。
章节身份在整份文档内唯一，不以轨道为作用域。
复制和重复导入 must 分配新身份。
合并生成新轨道身份，拆分为每条结果轨道生成新身份。
撤销恢复被替换轨道的原身份，重做复用首次结果身份。
行号和数组索引 must 不作为稳定身份。
编辑身份 must 不泄漏到不需要它的现有章节导出格式。

`StateId` can 随撤销返回旧值。
`MutationRevision` must 不随撤销返回旧值。
关闭或替换会话时，宿主 must 取消该会话的未完成任务。
运行实例令牌与文档身份 must 阻止旧会话任务提交到新会话。

### 3.4 文档不变量与适配边界

每个章节在当前状态中 must 只属于一条轨道。
章节移动 must 不隐式按时间排序。
默认允许相同起点和时间不递增的行序。
要求时间有序的工具或格式 must 报告诊断，不能静默排序。
显式排序属于一次内容事务。

`Kind = Separator` 表示可编辑的结构行。
结构行具有身份和名称，但不参与章节编号、时间计算和默认模板目标计数。
结构行 must 不同时充当片段边界的权威值。
按时间拆分时，结构行跟随原行序中的下一个标记；末尾结构行跟随前一个标记。
不存在标记时，结构行归入第一个结果片段。
工具目标按轨道顺序和行序枚举，must 不依赖选择集合的迭代顺序。

适配旧服务时，must 显式映射输入身份与输出身份。
位置映射只适用于已证明不增删、不重排的操作。
结构操作 must 返回身份映射或直接生成领域变更集。
导入、候选提交和历史恢复 must 使用相同的文档不变量。
历史恢复 must 不自动修正旧值。

## 4. 一致的编辑语义

### 4.1 所见值就是可编辑值

主表格 must 显示当前文档值。
单元格提交 must 修改用户看到的那个值。
主表格 must 不显示持续表达式变换后的替代值。
主表格 must 不保留“源值”和“输出值”两种编辑模式。

例如，当前章节时间为 `00:10:00`。
应用 `t + 5` 后，文档时间变为 `00:10:05`。
随后将单元格改为 `00:10:06`，文档时间就是 `00:10:06`。
导出时 must 不再次执行 `t + 5`。
撤销单元格编辑恢复 `00:10:05`。
继续撤销表达式应用恢复 `00:10:00`。

### 4.2 模板、表达式和批量工具

模板命名、自动命名、正则替换、整体偏移和表达式都使用同一流程。

```text
Capture current state and explicit target IDs
                    |
                    v
Compute candidate document
                    |
                    v
Validate complete result
                    |
                    v
Show optional before/after preview
                    |
                    v
Apply one atomic in-memory transaction
```

候选预览是临时只读数据。
它不是第二份工作文档。
取消预览 must 不修改文档或历史。
应用成功后，预览草稿结束。
工具参数 can 留在控件中，便于下一次使用。
参数保留 must 不表示规则仍在生效。

模板名称数不足时，默认只修改对应的前 N 个目标章节。
模板名称数超过目标数时，工具 must 报告未使用名称数。
空模板项默认跳过对应章节。
预览 must 明确标示跳过项。
无匹配结果不生成事务。

表达式上下文 must 来自操作开始时的完整快照。
后续章节的计算 must 不读取前面章节已修改的候选值。
候选计算中的单行错误、超时和取消 must 使整次应用失败。
负时间和数值溢出 must 拒绝提交。
截断或丢弃章节只有在用户显式选择对应操作策略时 may 执行。

再次点击“应用表达式”会基于当前文档再次计算。
这会形成新的事务。
界面 must 显示预计修改数量和关键差异。
界面 must 防止同一次按钮事件或请求重试被提交两次。
这通过 `TransactionId` 去重实现。

### 4.3 操作范围

工具 must 显式显示操作范围。
范围可以是当前轨道、选中章节或全部轨道。
默认范围是当前轨道。
工具 must 不把“无选择”隐式解释为“全部文档”。
目标身份在计算开始时固定。
应用时 must 校验文档身份和修改版本。
预览过期时，工具 must 要求重新计算。

时间字段编辑只修改指定章节字段。
若结果使 `EndTime < StartTime`，提交 must 失败。
整体平移 must 同时平移存在的开始时间和结束时间。
平移默认保留轨道总时长和片段边界。
越界结果 must 失败。
时基缩放 must 同时缩放开始时间、结束时间、总时长和片段边界。
缩放因子 must 为正数。
相同原始时间 must 映射到相同结果 ticks。
若舍入使片段长度变为零，提交 must 失败。
源媒体的原始入点和出点属于来源信息，must 不被时基缩放改写。
FPS 工具 must 区分“设置解释帧率”和“保持帧号转换时间”。
两种操作 must 使用不同名称和差异预览。

### 4.4 单元格编辑

开始编辑时，宿主 must 捕获章节身份、字段、原值和修改版本。
输入期间只更新草稿。
Enter、Tab 和有效的失焦提交形成一次事务。
Esc 丢弃草稿。
输入法组合期间 must 不提交。
无效输入 must 保留错误提示。
无效输入 must 不被静默替换为零。
旧编辑服务的警告、时间归零和负值过滤 must 不被直接视为成功候选。
删除后的时间归一化 must 同时更新保留章节的开始时间与显式结束时间。
它 must 使用第 4.3 节的平移校验规则。
提交相同规范值 must 不生成事务。

文本编辑状态下，撤销快捷键操作控件草稿。
离开编辑状态后，撤销快捷键操作文档历史。
文档撤销按钮 must 先取消未提交草稿，再撤销一条文档事务。
执行保存或其他内容命令前，宿主 must 提交有效草稿。
无效草稿 must 阻止依赖当前编辑结果的命令。
宿主 must 不静默导出与屏幕草稿不同的旧内容。

## 5. 合并、拆分与追加

### 5.1 合并修改当前结构

合并是一条内容事务。
合并将选定的当前轨道替换为一条合并轨道。
它 must 使用当前已编辑的章节。
它 must 保留章节名称、身份、结束时间和必要来源信息。
它 must 不默认重命名为 `Chapter 01` 等名称。
自动命名是另一条显式操作。

合并时，章节时间加上累计片段时长。
合并轨道保存片段边界与媒体放置信息。
边界数据不包含另一份章节内容。
每个片段 must 保存当前区间、片段身份、轨道元数据和媒体放置信息。
该数据是可编辑结构，must 随事务保存。
片段区间 must 连续覆盖合并轨道，且各区间长度为正。
合并前 must 校验各输入轨道时长与章节范围。
嵌套合并 must 将已有片段区间平移后展开，不能丢失内部边界。
默认编号起点继承首个轨道。
差异预览 must 显示编号变化。

具有不同有效帧率的轨道 must 先统一帧率策略再合并。
实现 must 不直接采用首个轨道帧率解释全部章节。

### 5.2 拆分使用当前内容

“恢复原片段”按钮改为“按片段边界拆分”。
拆分 must 使用合并轨道的当前章节。
它 must 不恢复合并前的隐藏备份。
拆分将章节开始时间减去所属片段的当前起点。
存在的结束时间 must 减去同一个起点。
拆分结果使用片段区间长度作为时长。
结果继承当前有效帧率和编号策略，并使用片段元数据恢复标题与媒体引用。
预览 must 显示这些元数据与编号变化。
章节归属按当前开始时间确定。
边界采用左闭右开区间。
恰好位于边界的章节属于后一个片段。
位于轨道总时长的标记属于最后一个片段。

章节跨越边界后，拆分会将它分配到新的片段。
名称和章节身份保持不变。
显式结束时间跨越片段边界时，拆分 must 报告冲突。
默认 must 不自动截断或复制章节。
用户 can 先调整结束时间再拆分。

直接修改章节时间不会自动移动片段边界。
修改边界属于独立事务。
时基缩放则同时缩放边界。
拆分后重新合并 must 基于拆分后的当前内容。

“撤销合并”与“按边界拆分”是不同操作。
前者恢复合并之前的完整状态。
后者保留合并之后的有效编辑。
两者都可撤销。

### 5.3 追加

追加先读取源，再计算候选状态。
已有合并轨道 must 保留当前编辑内容。
追加 must 不从导入原稿重新构造已有部分。
追加的媒体引用和边界 must 一并进入事务。
重做追加 must 使用历史中保留的结果。
重做 must 不重新读取文件。

## 6. 事务与可逆变更

### 6.1 提交入口

Core 提供一个逻辑提交入口。
每份文档会话拥有一个串行命令队列。
编辑、撤销、重做和历史切换 must 通过该队列提交。
候选计算 can 在队列外执行。
宿主 must 不直接修改当前文档集合。

接口职责如下。

```text
Prepare(operation, document, explicit targets)
  -> PreparedEdit(candidateId, baseToken, candidate, diagnostics, changeSet)

BaseToken = (documentId, instanceToken, mutationRevision, stateId)

Commit(transactionId, preparedEdit)
Undo(transactionId, baseToken)
Redo(transactionId, baseToken, optionalChildStateId)
Checkout(transactionId, baseToken, targetStateId)
  -> Applied | NoChange | Invalid | Stale | Cancelled | ResourceFailure
```

`Prepare` 只计算。
`PreparedEdit` must 绑定捕获的基准状态和不可变候选。
Core must 验证变更集应用到基准状态后等于候选。
宿主 must 不分别提交可互相矛盾的候选和变更集。
`Commit` 负责校验并原子替换内存会话状态。
`Checkout` 用于历史面板定位任意保留状态。
所有内容命令 must 按第 4.4 节处理活动草稿。
历史面板切换 must 先取消草稿，再切换状态。

### 6.2 历史记录与会话状态

```text
HistoryNode
  StateId
  ParentStateId
  TransactionId
  OperationKind
  DescriptionArguments
  CommitSequence
  Timestamp
  ChangeSet
  BeforeBookmark
  AfterBookmark

SessionState
  CurrentDocument
  CurrentStateId
  MutationRevision
  HistoryNodes
  ChildStateIds
  PreferredChildStateIds
  CompletedCommands
```

`Workspace` 持有一个当前 `SessionState` 引用。
文档、游标、历史索引、首选路径与已完成命令结果 must 作为同一状态发布。
根节点保存导入时的完整不可变文档。
根节点没有父节点和编辑变更集。
其他节点保存领域变更集。
实现 must 不使用任意 JSON 路径反射修改。

基本变更包括字段替换、章节插入、章节删除、顺序替换和轨道结构替换。
每种变更 must 保存恢复所需的旧值和新值。
删除 must 保存完整被删除条目及原位置。
结构变更 must 保存受影响轨道的前后结构。
大型批量变更 can 使用受影响轨道的完整前后快照。
正向和反向应用 must 使用同一份双向数据，避免重复保存相同负载。
反向应用 must 按相反顺序执行子变更。

每一步应用 must 验证目标身份、原位置或旧值等前置条件。
恢复结果 must 满足文档不变量。
事务内的全部子变更只形成一条历史节点。
失败操作和无变化操作 must 不创建节点。
描述使用稳定操作类型和本地化参数。
历史 must 不引用 UI 控件、事件处理器、取消令牌、任务或进程对象。

撤销和重做 must 不运行原始表达式或重新解析原文件。
它们只应用内存中保留的变更。
恢复校验失败 must 返回 `Invalid` 并保留当前游标和内容。
实现 must 报告历史状态不一致，不能静默跳过损坏节点。
本模型无需历史序列化格式、模式迁移、字节校验和或存储端口。

### 6.3 原子提交

1. 在隔离候选状态上计算全部结果。
2. 进入文档会话的串行命令队列。
3. 查询同一事务 ID 的已完成结果，再校验基准令牌与取消状态。
4. 校验身份、字段范围、变更前置条件和候选一致性。
5. 构建完整的新 `SessionState`，包括节点、索引、首选路径、游标、递增版本和命令结果。
6. 一次性替换当前 `SessionState` 引用。
7. 在提交完成后通知视图，并恢复选择书签。

步骤 6 是提交生效点。
步骤 6 之前 must 完成全部可能失败的计算、分配和校验。
实现 must 不先修改当前文档，再补写历史。
实现 must 不通过逐个修改共享字典来拼接已发布状态。
不可变集合 can 共享未变部分，避免每次复制整棵历史树。
读取方 must 捕获同一个会话快照，不能混用不同版本的文档和游标。

步骤 6 之前失败或取消时，旧状态保持不变。
步骤 6 不执行用户回调、异步等待或可取消工作。
步骤 6 之后到达的取消请求不能撤回提交。
视图通知失败不改变提交结果。
宿主 must 从当前会话快照重新刷新视图，不能重新执行业务操作。
其他内容命令 must 在当前提交结束后执行。
事件回调 must 不重入提交临界区。

### 6.4 命令去重与生命周期

`TransactionId` 同时适用于编辑提交和游标移动。
同一次事件分发或请求重试 must 复用原 ID。
一次新的用户操作 must 使用新 ID。
重新计算候选后提交也 must 使用新 ID。

`CompletedCommands` 在内存中记录成功操作的请求身份和结果。
请求身份包含命令种类、基准令牌及候选或目标状态身份。
候选准备时 must 分配稳定候选身份。
相同 ID 与相同请求返回原结果。
相同 ID 与不同请求 must 返回 `Invalid`。
原结果查询 must 先于过期版本拒绝。
结果记录 must 与文档和游标一起原子发布。

返回原结果不代表当前游标仍停留在该结果状态。
宿主 must 读取当前会话快照，不能因迟到通知回退显示。
结果记录只保存去重所需的身份与结果标识。
它 must 不额外保留整份候选、原始文件或操作闭包。
记录在会话内保留，随会话一起释放。
`NoChange` 不修改会话；相同基准上的重复请求仍返回 `NoChange`。
基准已变化时，无成功记录的旧请求返回 `Stale`。
本地内存提交具有明确生效点，无需持久化回执或通信结果确认协议。

## 7. 不限步数的撤销与重做

### 7.1 历史树与游标

每个新编辑节点只有一个父节点。
同一节点 can 有多个子节点。
当前状态由内存会话中的游标指向。

```text
S0 --> S1 --> S2 --> S3
              |
              +---> S4 --> S5
```

在 `S3` 撤销一次，游标到 `S2`。
在 `S2` 提交新编辑，创建 `S4`。
`S3` must 继续保留。
新操作 must 不删除旧重做分支。

撤销移动到父节点。
普通重做沿当前节点的首选子节点前进。
撤销时，刚离开的子节点成为首选重做节点。
新提交的子节点也成为首选重做节点。
显式重做某个子节点时，该子节点成为首选。
用户 can 从历史分支入口选择其他子节点。
所有首选路径保留在当前会话中。
历史排序使用单调提交序号，时间戳仅用于显示。
序号 must 不作为历史条数限制。

失败操作、草稿修改、选择行和切换轨道 must 不改变历史分支。
撤销和重做只移动游标，不产生新的内容节点。
游标、当前文档及首选路径 must 一起原子更新。
`Redo` 指定的状态 must 是当前节点的直接子节点。
根节点撤销、无子节点重做、定位当前状态均返回 `NoChange`。
这些操作 must 不增加版本或改变首选路径。

### 7.2 跨分支切换

`Checkout` must 验证目标属于同一文档会话。
跨分支切换先计算当前节点与目标节点的最近公共祖先。
实现 must 在隔离状态中反向应用变更到祖先，再正向应用到目标。
路径上的每步 must 验证变更前置条件。
路径遍历 must 使用迭代算法，不能依赖随历史深度增长的递归调用栈。

宿主只在全部恢复成功后发布目标状态。
中间状态 must 不对外发布。
跨越任意多个节点只增加一次修改版本。
离开路径按撤销规则更新首选子节点。
到达路径再按重做规则更新首选子节点。
到达路径优先决定公共祖先处的首选分支。
不在本次路径上的首选项保持不变。
目标状态已有的首选子节点保持不变。

### 7.3 操作分组

一次单元格编辑会话形成一条事务。
一次批量操作形成一条事务。
同一数值拖动手势形成一条事务。
显式确认、保存、切换工具或更换编辑目标 must 结束当前分组。
已提交节点 must 不被后续输入原地修改。
分组在草稿阶段完成。
历史记录保留全部已提交事务。
产品不承诺保存每次未提交的键入或鼠标采样。

### 7.4 内存所有权与资源处理

Core 的文档会话拥有历史树及其全部负载。
桌面和浏览器 must 使用相同的 Core 内存历史实现。
宿主只负责命令绑定、通知与会话生命周期。
CLI 和 Node.js 的普通转换调用直接使用纯业务操作，无需创建历史会话。

根快照、领域变更集和历史索引 must 在会话有效期内保持可达。
未变化的轨道、章节和集合节点 must 尽可能共享不可变引用。
单字段修改 must 不复制全部轨道或全部历史节点。
批量结构替换只保留受影响结构的前后状态。
实现 must 不为每个历史节点额外保存整份文档快照。
当前文档与历史负载 can 共享对象，不能修改共享对象。

历史面板 must 使用虚拟化视图，并按需构造显示项。
这只限制 UI 对象的数量，不截断内存中的历史。
不引入历史落盘、压缩文件、数据库或浏览器存储适配器。
不引入独立检查点系统；跨分支恢复使用根快照与领域变更集。
性能验收 must 同时衡量变更集内存与恢复路径耗时。

内存占用 can 随历史长度增长。
可恢复的资源不足 must 返回 `ResourceFailure`。
宿主 must 保留原文档、游标和历史。
宿主 must 保留已存在的输入草稿，便于用户调整操作或导出当前内容。
失败候选与临时重建状态 must 释放，不能为了重试继续占用其全部内存。
实现 must 不自动删除旧历史来完成新操作。

### 7.5 会话释放

执行应用内关闭、替换或重新加载命令前，宿主 must 说明该操作会结束当前撤销历史。
会话存在编辑历史、活动草稿或未导出内容时，宿主 must 提供继续与取消选择。
关闭确认 can 与现有未保存内容确认合并。
没有编辑历史且内容未修改时无需额外确认。
章节导出不包含历史；确认界面 must 不将导出描述为保留撤销能力。
浏览器刷新、强制退出和进程终止可能绕过应用内确认。
宿主 must 在历史面板标明会话有效期，不能承诺这些情况下可拦截退出或恢复历史。

会话结束后，宿主 must 取消任务并解除事件订阅。
历史树、命令结果、草稿、预览及 UI 显示项 must 解除引用。
已开始的只读导出 can 持有捕获的内容快照直至完成。
它 must 不持有整份历史会话。
本功能不增加单独的清除历史命令或后台会话恢复列表。

## 8. 多轨道、异步操作与会话隔离

一份文档拥有一棵历史树。
全部轨道共享这棵树。
先修改 A，再修改 B，撤销顺序为 B、A。
切换轨道 must 不创建或清空历史。
撤销时，宿主 must 定位到受影响轨道和章节。
选择书签不属于内容状态。
它保存在事务上下文中。
界面恢复书签失败时，内容恢复仍然成功。
界面 can 选择最近的有效行。

异步任务捕获完整 `BaseToken` 和目标身份。
提交时 must 校验全部令牌。
编辑到其他状态后又撤销回相同内容，版本仍然增加。
旧任务因此不能提交。
过期的批量结果 must 重新计算，不能自动重定位或合并。

打开其他源或重新加载源会创建新文档会话与新历史根。
宿主 must 先完成导入与新会话构建，再按第 7.5 节确认替换。
等待确认期间旧会话有新修改时，宿主 must 重新检查替换条件。
导入失败、构建失败或用户取消 must 保留原会话。
替换成功后，旧历史释放。
重新打开同一路径也会创建新 `DocumentId`，不恢复旧历史。
追加属于当前会话中的编辑事务，不创建新根。

多个窗口或标签页独立打开同一文件时，各自拥有独立文档会话。
它们 must 不共享历史、游标或版本。
本方案不增加跨进程锁、标签页协调或实时协作。
同一会话的多个视图 must 共享一个 Core 会话实例与命令队列。
异步导出结果只能更新所属会话的导出基线，不能更新后来打开的新会话。

## 9. 预览、导出与保存状态

格式预览和导出使用同一纯序列化入口。
二者 must 捕获相同类型的文档快照和格式选项。
格式选项只包含格式、编码、BOM、语言和格式必需的元数据。
序列化 must 不改名、偏移时间或执行表达式。
序列化 can 按目标格式处理分隔行、精度和不支持的字段。
格式能力损失 must 通过诊断报告。
这些格式适配 must 不回写当前文档。

批量工具的候选预览必须使用独立标识。
它 must 不冒充主表格或格式预览的当前内容。
保存前，界面 must 处理活动草稿。
它 must 不自动把未确认的工具候选应用到文档。

保存动作在本方案中指章节导出。
单轨道导出成功只能确认对应内容已导出。
它 must 不把其他轨道标记为已导出。
成功导出记录轨道内容摘要、格式选项和对应 `StateId`。
摘要 must 排除选择、日志、缓存和帧显示文本。
摘要 must 包含实际参与该格式导出的规范内容。
内容恢复到相同摘要时，可以恢复“与上次导出一致”的状态。

异步导出 must 绑定开始时捕获的快照。
完成时 must 不把期间新增编辑标记为已导出。
导出失败 must 不更新基线。
导出 must 不清空撤销历史。
导出基线仅存在于当前会话中。
“已应用”表示内存事务已完成。
“已导出”表示捕获的内容已成功输出。
界面 must 分别报告两种状态，不能将内存编辑描述为已保存到文件。
本功能不增加工程文件格式或历史保存点。

## 10. 用户界面

删除“持续应用表达式”和“持续模板命名”的开关语义。
保留表达式编辑器和模板选择器。
工具提供“预览”和“应用”动作。
主表格始终展示当前文档。

主工具栏提供撤销与重做。
按钮名称包含下一次操作描述。
示例为“撤销：删除 3 个章节”。
多个重做分支通过重做按钮的分支入口选择。
历史面板按需构造树节点的显示项。
历史面板 must 标明当前状态和首选路径。

Windows 和 Linux 默认使用 `Ctrl+Z` 撤销。
默认提供 `Ctrl+Y` 和 `Ctrl+Shift+Z` 重做。
macOS 默认使用 `Cmd+Z` 和 `Cmd+Shift+Z`。
快捷键 must 接入现有快捷键目录和冲突检查。
文本控件 must 保留自己的草稿撤销作用域。

历史恢复期间，内容修改命令暂时不可执行。
日志追加、状态刷新和选择恢复 must 不创建历史记录。
状态栏 must 区分处理中、提交失败和提交成功。
“已应用”只能在历史事务完成后显示。

## 11. 迁移与兼容边界

迁移 must 不保留交互宿主中的双重内容模型。
完成切换后，旧投影路径不得继续参与表格、预览或导出。

CLI 的 `--expression` 和 `--expression-preset` 保留用户语义。
CLI must 先执行一次内容变换，再调用纯序列化入口。
这些参数不是序列化选项。
CLI 参数仍通过 `DotMake.CommandLine` 定义与绑定。

公开 Core 和 Node.js 接口的现有行为必须有迁移路径。
兼容入口 can 把旧选项转换为一次性操作，再调用新序列化入口。
兼容入口 must 不在交互文档中保存持续规则。
每次兼容调用 must 只执行一次变换，并将结果传给纯序列化入口。
无状态调用无法识别调用方传入的内容是否已经变换。
调用方复用变换结果时 must 使用纯序列化入口，不能再传入变换选项。
旧接口的弃用与删除 must 遵循明确的版本策略。

设置中的旧自动命名或表达式开关 must 不被恢复为活动规则。
设置迁移 can 保留工具文本和默认参数。
首次打开时，工具显示“待应用”。
编号偏移迁移为文档编号策略的显式修改。
现有设置保存 can 保持原行为，但 must 不写入文档历史。

## 12. 实施顺序与完成条件

以下步骤组成同一项完整实施。
每一步都 must 完成，不能以暂时禁用已有编辑功能作为最终交付。

| 步骤 | 实施内容 | 完成条件 |
| --- | --- | --- |
| 1 | 定义不可变文档、稳定身份、时间规则和纯序列化边界 | 表格、预览与导出读取同一当前内容；旧数据类型适配不保留第二份编辑状态 |
| 2 | 实现领域变更集、内存会话状态和统一命令队列 | 原子提交、前置校验、取消与命令去重通过 Core 测试 |
| 3 | 实现历史树、撤销、重做和跨分支切换 | 所有保留节点可达；首选路径符合第 7 节；无自动截断 |
| 4 | 将全部内容操作接入候选计算 | 单元格、插入、删除、排序、编号、模板、表达式、偏移、FPS 与元数据修改都形成可逆事务 |
| 5 | 重写合并、拆分和追加 | 当前编辑、身份、结束时间、片段边界和来源信息完整保留 |
| 6 | 接入 Avalonia 与浏览器交互 | 两个宿主均使用 Core 内存会话；草稿、预览、快捷键、分支入口与历史面板行为一致 |
| 7 | 完成会话生命周期与导出基线 | 打开、重新加载、关闭、取消和异步导出遵守会话隔离；结束会话后释放历史 |
| 8 | 完成 Core、CLI 和 Node.js 兼容入口 | 旧参数转换为一次性操作；内容不重复变换；普通转换调用不创建历史 |
| 9 | 移除旧交互投影与直接修改路径，更新代码地图 | 全部已有编辑入口完成迁移；所有相关测试与性能验收完成 |

实施中 must 逐项盘点宿主的内容修改入口，并记录对应事务和行为测试。
同一可编辑文档 must 不混用旧直接修改入口与新历史入口。
旧模型的切换 must 在完整事务链可用后进行。
迁移完成后，内容命令的可用性只由文档条件与运行状态决定。
不能因未完成迁移而留下永久禁用的命令。
本功能的交付不依赖历史数据库、存储适配器或后续补充阶段。

## 13. 验收要求

### 13.1 行为验收

| 场景 | 必须结果 |
| --- | --- |
| 应用表达式后改时间，再保存 | 保存单元格中的当前时间；表达式不重复执行 |
| 应用模板后手动改名 | 表格、TXT、XML、JSON 和其他支持名称的格式读取当前名称 |
| 操作失败、提交前取消或结果不变 | 内容、历史节点和首选重做路径不变 |
| 修改全部章节时一行无效 | 全部修改拒绝提交 |
| 插入、删除、移动后撤销与重做 | 值、顺序、身份和有效选择恢复 |
| 改 A，再改 B，然后连续撤销 | 先恢复 B，再恢复 A |
| 合并后改名，再按边界拆分 | 名称保留；不读取合并前章节备份 |
| 合并后追加 | 已有编辑保留，新增内容形成一次事务 |
| 时间跨边界或结束时间跨片段 | 执行确定的归属规则或报告明确冲突 |
| 撤销后产生新分支 | 旧分支仍能选择并重做 |
| 大量编辑后撤销到根，再沿各分支重做 | 所有已提交状态仍可恢复，没有步数截断 |
| 根节点撤销、叶节点重做或定位当前状态 | 返回 NoChange，不增加版本 |
| 提交前注入可恢复分配失败 | 原文档、游标与历史保持一致，释放临时候选 |
| 提交成功但视图通知失败后重试 | 同一事务只生效一次，视图从当前会话刷新 |
| 撤销、重做或切换重复提交 | 返回原结果，不再次移动游标 |
| 相同事务 ID 携带不同请求 | 拒绝请求，内容与游标不变 |
| 旧命令通知在后续编辑完成后到达 | 不回退显示，不重复发布旧状态 |
| 跨分支重建在提交前失败或取消 | 不发布中间状态，不移动游标 |
| 取消发生在原子替换之后 | 返回已应用结果，不将成功提交报告为取消 |
| 旧任务遇到编辑后又撤销 | 因修改版本不同而拒绝提交 |
| 未知时长的纯文本章节编辑 | 不将未知时长当作零上界 |
| 复制、重复导入、合并和拆分后重做 | 身份唯一，重做复用首次结果身份 |
| 分隔行参与模板、编号和拆分 | 遵守结构行规则，不改变标记目标计数 |
| 删除并归一化包含结束时间的章节 | 起止时间同步平移，可完整撤销 |
| 会话内源文件已移动或删除 | 撤销、重做和分支切换仍使用内存负载完成 |
| 导出期间继续编辑 | 新编辑仍被识别为与上次导出不同 |
| 导出期间打开另一个文档 | 旧导出完成不能更新新文档的导出基线 |
| 导出成功后继续撤销 | 当前会话全部历史保留 |
| 导入或新会话构建失败 | 原工作区和历史保持可用 |
| 取消关闭、替换或重新加载 | 原会话、草稿和历史保留 |
| 确认关闭或替换会话 | 旧任务失效，历史和相关 UI 对象解除引用 |
| 应用重启或浏览器页面刷新 | 不恢复历史，重新导入创建新根 |
| 不同窗口或标签页打开同一文件 | 会话与历史相互独立 |
| 同一会话的多个视图操作 | 经同一命令队列提交，观察一致快照 |

### 13.2 内核与资源验证

Core 测试 must 验证正向变更与反向变更的组合恒等性。
属性测试 must 将随机编辑、撤销、重做、重试和分支切换与完整快照参考模型比较。
比较 must 包含全部规范内容与身份，不能只比较章节数量。
操作序列测试 must 覆盖多次分支切换及过期任务。
原子提交测试 must 在候选构建、历史索引构建和视图通知处注入故障。
可恢复分配失败 must 通过故障注入验证，不能依赖耗尽测试进程内存。

大历史测试 must 逐级增加提交次数与分支数。
测试 must 覆盖单字段修改、大批量修改和结构变更。
测试 must 记录托管内存、每次编辑分配量、撤销耗时与远距离切换耗时。
单字段修改的历史负载 must 随实际变化增长，不能为每步复制整份文档。
深历史遍历 must 不发生调用栈溢出。
历史面板创建的显示项数量 must 受可见区域与展开范围约束。
性能报告 must 记录测试数据规模与运行环境。
固定条数的测试不能证明物理上的无限内存。
实现审核 must 确认没有按条数、时间或内存占用自动截断历史的路径。

会话释放测试 must 验证历史、草稿和视图订阅不再被宿主持有。
测试 must 单独验证进行中的导出只保留内容快照。
测试 can 使用弱引用与受控垃圾回收检查对象可回收性。
测试 must 不将进程工作集立即下降作为释放成功条件。

### 13.3 宿主验证与命令

Avalonia 非 Headless 测试覆盖会话编排、导出与异步任务隔离。
Headless 测试覆盖编辑提交、Esc、焦点、快捷键作用域和分支选择。
浏览器测试覆盖相同的编辑流程，以及标签页独立和刷新后新会话行为。
CLI 与 Node.js 验证一次性变换及纯序列化兼容行为。
所有测试 must 使用运行时行为或公共 API，不能读取源码文本代替验证。
Headless 测试与非 Headless 测试 must 保持进程隔离。

实现完成后，按仓库要求先恢复依赖，再顺序运行测试。
跨项目的统一模型变更 must 执行：

```text
dotnet test ChapterTool.slnx --no-restore
```

Node.js 与浏览器专项验证 must 按对应代码地图和项目脚本执行。
相关 UI 布局变更 must 提供默认、宽和窄尺寸截图。
实施报告 must 列明实际执行命令、性能数据和未完成检查。
本文档修改本身不要求 .NET 构建或测试。

## 14. 参考设计与适用范围

- [Qt Undo Framework](https://doc.qt.io/qt-6/qundostack.html)：借鉴事务分组、操作描述和保存点。
- [CodeMirror history](https://codemirror.net/docs/ref/#commands.history)：借鉴编辑分组与显式历史边界。
- [ProseMirror history 实现](https://github.com/ProseMirror/prosemirror-history/blob/master/src/history.ts)：借鉴事务标记和选择书签。
- [Immer patches](https://immerjs.github.io/immer/patches/)：借鉴可逆变更与不可变状态。

本方案不要求引入上述框架。
本方案不声称这些参考实现默认保留无限历史或全部分支。
会话内保留全部分支、不主动截断历史和纯内存所有权是本项目的明确设计决策。
