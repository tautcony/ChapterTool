## 跨模块共性问题

1. **不可信输入解析缺乏统一防御边界（最集中的风险区）**。Core 的多个导入器（XPL、CUE、XML、FLAC、IFO/TAK）在畸形输入下直接崩溃或无上限分配内存：未捕获的算术异常（CORE-01/03）、编码异常（CORE-02）、不可寻址流（CORE-10/11）、无深度限制递归（CORE-14）、绕过 `PortableInputPolicy` 的无上限拷贝（CORE-13）。建议在导入器入口建立统一的"畸形输入 → 结构化导入错误"转换层，并为全部导入器补充畸形输入测试。
2. **时间计算与格式化正确性**。CORE-04/05/06/07/08 全部集中在时间轴计算与格式化：uint 回绕、进位错误、格式支持不全、负时长入模型。章节工具的核心价值就是时间精度，建议把时间格式化/解析收敛到单一经过属性测试（property-based test）覆盖的组件。
3. **异常处理策略不一致**。同类操作在不同位置的异常处理不一致：`ShellService.OpenAsync` 无兜底而同类方法有（INFRA-05）；BDMV 扫描只捕获 `IOException` 漏掉 `UnauthorizedAccessException`（INFRA-06）；UI 命令层部分 ViewModel 未注入 `ErrorHandler`，错误被静默吞掉（UI-02/04）；Node API 部分路径返回结构化诊断、部分路径抛裸异常（HOST-05）。建议明确每层的异常契约并统一。
4. **非 UTF-8 编码处理**。CORE-02（CUE 崩溃）、CORE-09（静默乱码无诊断）、HOST-01（Windows 控制台中文乱码）构成同一主题：对遗留编码（GBK/Shift-JIS）输入与控制台输出缺乏策略。
5. **测试缺口与产品风险重合**。CLI 导入错误分支完全无测试（TEST-04），而 INFRA-01（高）恰好位于 CLI 导入路径；Core 解析器的崩溃系列说明缺少畸形输入用例；BDMV 测试因环境门控永久假绿（TEST-01）。补测试时应优先覆盖这些已知缺陷区。
