## Context

第一版以独立结果区域展示候选，解决了重叠问题，但仍降低章节可视区域高度。
用户进一步明确要求在原章节表内比对。
本设计采用同一章节行、同一单元格中的原值与预览值。
原内容仍是已提交文档，预览是只读候选投影。
帧的原值必须从候选出现之前同一行可见的 `FramesInfo` 捕获。
候选投影不能用 Core 中的缺失标记覆盖显示帧率已计算出的值。

## Goals / Non-Goals

**Goals:**

- 不增加底部结果区域或独立逐章审阅弹框。
- 原章节位置、选择和滚动必须在预览过程中保持。
- 时间、名称、编号及帧值必须在其对应单元格中比较。
- 图标和语义颜色必须区分已提交值与尚未应用的值，且保留无障碍名称和工具提示。
- 应用和放弃必须使用同一候选及既有原子事务。

**Non-Goals:**

- 不修改历史弹框、Core 事务或独立 Expression 工具的既有编辑流程。
- 不默认隐藏未变化章节，不引入排序或第二套章节行。
- 不把预览值直接写入现有可编辑字段。
- 不修改 Blazor 或 CLI。

## Decisions

### 1. 同格比较是默认表格模式

宽窗口中，变化单元格显示原值、箭头图标和预览值。
时间单元格同时显示带符号的变化量。
原值用次要文本，目标值使用语义强调。
表头保持简短的时间、名称、帧和编号。
单元格不得显示“原/预览”或 `Original/Preview` 文本标签。
未变化单元格仍只显示原值。
箭头图标、语义颜色及 accessible name 和 tooltip 必须说明原值与预览值，不能只依赖颜色。

窄窗口使用两行单元格，每行显示一个值及紧凑箭头提示。
该模式可以增加行高，但必须保留表格可视区域的分配高度。
不能通过缩小字体或覆盖文字挤入两份时间。
合理设置列最小宽度。
确有必要时，仅在表格内提供横向滚动。

时间、帧、名称和编号必须按实际变化分别比较。
帧原值使用准备候选之前行中可见的 `FramesInfo` 快照。
原帧的准确、近似或中性颜色也必须在同一时刻从可见行捕获。
候选帧使用候选的 `FrameAccuracy`，不能统一覆盖为预览强调色。
准确和近似值复用普通帧列的语义颜色，中性值保持普通中性颜色。
如果当时没有可见计算值，才显示本地化缺失值。
快照按稳定轨道和章节 ID 绑定，并在候选准备、输入变化和投影刷新期间保持。
表格主视图不能输出长帧率分数或原始对象描述。

交互原型同时展示同格比较和追加预览列。
同格比较保持原有列结构，更适合当前小窗口。
追加预览列在宽屏下有更好的跨行扫描效果，但多字段变化会扩张表宽。
当前实施选择同格比较；追加列仅为设计对照。

### 2. 原表格复用同一套稳定章节行

预览数据必须按轨道 ID 和章节 ID 映射到原章节行。
不能按当前行索引、显示编号或名称匹配。
只使用当前候选的基础快照和目标快照。
不得从技术字符串解析对比值。

展示模型可以为每个行对象附加只读比较投影。
不得修改正常编辑使用的 `TimeText`、名称或帧字段来模拟预览。
不创建第二个内容会话或第二套结果列表。
原有排序、选择、滚动及虚拟化必须保持。
全部未变化章节继续留在原位置。

正常内容编辑必须先结束预览。
有效候选展示期间表格只读。
滚动、选择和编辑表达式继续可用。
准备候选前，现有单元格草稿必须按已有提交或取消规则结束。
表格锁定必须同步禁用插入、删除及其他直接内容变更入口。
历史导航、换轨或文档替换仍可能使候选过期，必须走既有失效机制。
表达式编辑器的撤销继续作用于草稿。

### 3. 确认操作保留在现有操作槽

表达式所在行不显示章节摘要、摘要范围工具提示或重复章节详情按钮。
表达式所在行显示应用、放弃和可用的更新操作。
工具提示或现有诊断反馈只呈现无法由章节单元格表示的属性变化和错误。
其他内容操作复用这一状态，不能误标为表达式。
计算中显示简短状态，旧结果立即失效。
错误和过期状态禁用应用，并清除可被误认为当前结果的目标值。

文档或轨道属性变化无法放入章节单元格。
现有应用操作的本地化工具提示展示这些属性的范围和差异。
属性独立变化也必须可审阅和提交。
技术错误使用现有错误反馈，不增加重复详情浮层。

### 4. 应用与放弃恢复普通表格

应用必须提交当前表格展示的同一有效候选。
不能重新执行表达式。
成功后目标值成为普通表格的已提交值，原值和变化标识消失。
一次撤销必须恢复全部内容效果。
表格恢复编辑，并尽可能保留章节选择和滚动。

放弃必须取消候选，移除所有目标值并恢复普通表格。
原章节内容必须保持不变。
主窗口表达式草稿保留。
被放弃的同一草稿版本不能立即被定时器重新准备。
下一次输入修改或显式准备才恢复预览。

准备、响应式切换及保存不能提交候选。
保存继续使用已提交内容。
无变化时不能创建空事务。
提交中必须禁止重复应用及候选替换。
失败必须保留草稿并说明恢复动作。

### 5. 验收测量可视区域，而不是要求所有行同高

预览前后章节表格的可视区域边界必须相同。
宽窗口同格比较尽可能保持正常行高。
窄窗口允许两行布局增加行高。
两者都不能重新引入底部大面板。
测试必须检查有差异的单元格与未变化单元格。
必须检查滚动到末行后的身份对应。
截图必须覆盖中文、英文、760×600、1280×800 和 760×520。

## Risks / Trade-offs

- [双值增加单元格密度] → 宽窗横向比较，窄窗上下比较。采用合理列宽及可展开完整值。
- [预览与实际编辑混淆] → 箭头图标、语义颜色、可访问名称和工具提示标记预览值。只在应用后写入已提交字段。
- [用户想直接修改某行] → 明确提供放弃操作。结束预览后恢复原编辑入口。
- [按行索引映射产生错位] → 使用稳定轨道与章节身份。验证名称重复、编号变化及虚拟化。
- [元数据变化没有行位置] → 在应用操作的本地化工具提示中显示文档、轨道或分段差异，并保留属性独立变化的应用条件。
- [前一版规格要求独立区域] → 按先第一版后本 change 的顺序同步。以本次原表格审阅要求替换冲突条款。

## Migration Plan

1. 加入表格可视区域及原值未被预览写入的回归用例。
2. 增加稳定身份映射和只读行比较投影。
3. 增加同格比较模板及响应式列宽，并保留预览前可见帧值。
4. 将底部结果区替换为原操作槽中的应用、放弃、更新和必要错误反馈。
5. 移除重复章节摘要及逐章详情浮层，并验证应用工具提示中的非章节属性差异。
6. 对齐底部选项输入，更新翻译、代码地图和尺寸截图。

不需要数据或设置迁移。
第一版未提交实现必须保持。
第一版实现和测试已经存在于工作区。本次更新扩展同一 change，不新增平行 change。
