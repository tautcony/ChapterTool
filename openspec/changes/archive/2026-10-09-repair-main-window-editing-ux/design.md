## Context

本 change 依据用户提供的两张桌面截图。
第一张显示右侧常驻历史和章节列表下方的空白。
第二张显示表达式差异覆盖 XML 语言和表达式输入。
这些现象与当前代码中的布局和展示路径一致。

| 证据位置 | 当前行为 | 修正方向 |
| --- | --- | --- |
| `MainView.axaml` 中央 Grid | 两个默认 star 行。表格位于第一行，空状态位于第二行 | 表格和空状态使用同一个完整工作区 |
| `MainView.axaml` 历史 Border；`MainWindowViewModel.cs` | 固定 220 宽侧栏。`isHistoryPanelExpanded` 默认开启 | 历史按钮打开独立弹框 |
| `MainView.axaml.cs` 的 `ApplyAdvancedOptionsLayout` | 宽布局重建两行，窄布局重建三行。预览仍留在 `Grid.Row=3` | 每个布局状态必须为预览分配有效独立区域 |
| `MainWindowViewModel.Editing.cs` 的 `BuildExpressionPreviewText` | 直接输出差异字段和值，并取前六条 | 使用 typed snapshot 和业务格式 |
| `MainWindowViewModel.Commands.cs` 的选项预览 | 差异摘要仅写入状态文本 | 所有待确认内容操作必须具有可检查的预览入口 |

`MainWindow` 当前默认尺寸为 760×600，最小尺寸为 760×520。
底部选项宽窄切换阈值为 860。
尺寸均指 Avalonia 逻辑单位。

既有 `unified-editing-06-host-workflows` 和 `unify-expression-preview-interaction` 已完成任务，但仍在活动 change 目录中。
其规格包含历史分支和 typed candidate 语义。
本 change 必须保留这些语义。
实现前必须重新检查活动 change 与主规格。
本 change 不同步或归档其他 change。
`modernize-main-window-ux` 当前没有可供实现的完整制品。
本 change 独立定义截图所示回归的边界。

## Goals / Non-Goals

**Goals:**

- 历史只在按钮打开的弹框中显示。
- 章节表格使用中央工作区的完整宽度和高度。
- 表格、空状态、底部选项、预览和状态条必须有明确布局边界。
- 表达式、命名和其他内容操作的预览必须可读、可滚动和可确认。
- 尺寸切换必须保留草稿、候选、选择和历史状态。
- 验收必须包含交互结果和实际控件边界。

**Non-Goals:**

- 不进行完整主题或导航重设计。
- 不修改 Blazor 页面布局或 CLI。
- 不新增持久化历史，不改变 Core 历史树。
- 不改写 Lua 执行、内容事务或导出算法。
- 不扩展为全部辅助窗口的 UX 整改。

## Decisions

### 1. 历史使用现有辅助工具宿主

历史按钮必须执行打开命令。
主窗口必须移除历史侧栏及其占位列。
增加稳定 `ToolIds.History`、工具描述和历史视图。
桌面描述必须设置 `IsModal`。
已有 Embedded 宿主必须通过同一协议提供次级展示，不能重新引入常驻侧栏。

历史视图必须使用窄会话端口读取条目和命令状态。
它必须调用现有撤销、重做和按节点 ID 导航路径。
它不能持有第二个历史树或接收完整 `MainWindowViewModel`。
弹框打开期间的命令结果必须刷新当前节点和分支。
关闭必须释放订阅并归还焦点。
重复打开必须激活已有弹框。
无可用会话时历史按钮必须禁用。

曾考虑默认折叠侧栏和按钮 Flyout。
折叠侧栏仍会在打开后改变章节区域。
Flyout 不适合长历史列表和分支导航。
模态工具沿用现有生命周期和键盘隔离机制。

### 2. 中央区域只分配一个章节工作区

中央 Grid 必须保留一个可伸展工作区。
章节表格必须填充该区域。
空状态必须覆盖同一区域，并保持 `IsHitTestVisible=False`。
已加载章节必须隐藏空状态。
表格的滚动和虚拟化必须继续工作。
列必须保留稳定身份和合理最小宽度。

曾考虑只给表格增加 `RowSpan`。
这能遮住空白，但保留了不必要的双行布局和不同的空状态位置。
共享工作区能直接表达加载与空状态的关系。

### 3. 预览独立于选项表单的行重排

底部区域必须由选项表单和独立预览容器组成。
`ApplyAdvancedOptionsLayout` 只管理表单的宽窄重排。
预览容器必须在两种布局中具有明确的高度和滚动边界。
长结果必须在结果区域滚动。
确认和取消操作必须位于结果滚动区之外。
短窗口必须限制预览占用，并保留可用章节区域和状态条。
无预览时容器必须折叠，不能留下空白。

保留主窗口输入后自动准备候选的入口。
保留独立 Expression 工具的完整编辑流程。
主窗口预览可以显示有限数量的紧凑比较行。
它必须同时显示完整计数、截取说明和完整差异入口。
完整差异视图必须展示同一个候选，不能通过重新计算替换待确认内容。
命名、编号偏移和帧率操作也必须使用可检查的预览容器。

曾考虑继续增加 `ExpressionPreviewText.MaxHeight`，或将全部表达式输入强制移入弹框。
增加高度不能修复无效行和缺失完整差异。
强制弹框会改变截图中现有的快速编辑流程。
独立结果容器可以保留入口并修复空间分配。

### 4. 预览使用已有 typed comparison

表达式比较必须复用 `ExpressionPreviewProjector` 和既有行展示模型的格式规则。
其他操作必须从 typed candidate 的原值和目标值生成业务字段。
不能解析技术摘要字符串来生成 UI。
时间必须使用能分辨实际变化的格式。
帧值必须标明帧率依据。
时间变化、帧信息更新和属性变化必须分组计数。
缺失值必须区别于零。
错误必须与有效结果分开显示。
状态条只显示简短本地化状态。

候选所有权必须保持单一。
输入变化必须立即使原候选不可应用。
应用必须提交当前已展示候选。
取消必须终止待处理工作。
失败或过期必须保留草稿并显示可理解的恢复入口。
布局切换不能重新计算或提交候选。

### 5. 验收覆盖整个窗口和真实操作

验收尺寸必须包括 760×600、1280×800 和 760×520。
还必须包括 860 与 861 的阈值两侧，以及宽→窄→宽的连续切换。
每个主要状态必须包含中文和英文。
代表性状态必须检查放大字体和浅色、深色主题。

Headless 必须加载真实窗口、生产资源和确定性数据。
必须验证同坐标系下的控件边界、滚动可达性和实际按钮操作。
章节表格边界必须覆盖中央分配区，不能只验证控件存在。
预览内容和选项控件边界必须不相交。
截图必须写入 `artifacts/main-window-editing-ux/` 并人工复核。
截图不能替代行为断言。
Headless 与非 Headless 测试必须在独立进程中顺序执行。

## Risks / Trade-offs

- [历史弹框增加点击] → 保留主窗口撤销和重做快捷键。弹框必须保留全部导航操作。
- [小窗口被长预览挤占] → 限制结果区域高度。提供滚动和完整差异入口。检查最小窗口的控件边界。
- [两种表达式入口显示不一致] → 复用 typed projector 和格式规则。用同一候选 fixture 比较展示结果。
- [多种候选共用操作区导致错误提交] → 展示明确的操作名称和作用范围。应用绑定当前候选身份和版本。
- [弹框留下会话订阅] → 关闭后释放订阅。覆盖反复开关和内容树分离。
- [布局断言过于固定] → 按分配区、包含关系和不相交关系验收。只对最低可用边界采用数值约束。

## Migration Plan

1. 先添加失败的布局和交互回归用例。
2. 引入历史工具，移除侧栏展示状态。
3. 合并章节工作区，分离表单和预览容器。
4. 统一预览业务格式和完整差异入口。
5. 运行受影响测试，复核三种尺寸截图。
6. 更新 code map 和翻译投影。

无数据或设置迁移。
回滚使用普通代码回滚。
现有文档会话和输出文件格式不变。
