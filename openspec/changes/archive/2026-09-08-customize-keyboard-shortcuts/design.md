## Context

快捷键目前由 `ShortcutRouter` 的字符串 switch、主窗口 XAML 的 `InputGesture` 和本地化提示分别维护。设置文档使用统一的 `ChapterToolSettings` 聚合存储，设置工具已经具备草稿、实时应用、保存、重置和放弃生命周期。详见 `proposal.md` 及本变更的 capability specs。

## Goals / Non-Goals

**Goals:**

- 建立单一快捷键动作目录，供路由、菜单显示、设置编辑和测试共享。
- 将快捷键覆盖值纳入现有版本化设置聚合，并保持旧文档默认行为。
- 在设置 Tab 中提供键盘录入、冲突校验、逐项重置、全部恢复和保存/放弃反馈。
- 通过 Avalonia Headless 驱动真实视图和命令，验证用户可观察的完整流程。

**Non-Goals:**

- 不改变命令本身的业务语义或增加新的主窗口操作。
- 不支持宏、序列快捷键、鼠标手势或跨设备同步。
- 不要求 Wasm 浏览器端提供同等的可编辑快捷键 UI；浏览器默认快捷键拦截继续使用其现有保护逻辑。

## Decisions

1. **稳定动作标识符 + 独立手势值**
   - 为每个动作定义不可本地化的 ID，显示名称和默认 `KeyGesture` 分开存储。运行时使用 ID 查找命令，避免语言变化或菜单文本变化破坏映射。
   - 备选方案：直接以菜单标题作为键。放弃原因是本地化和重命名会造成设置迁移问题。

2. **共享运行时映射服务**
   - 由一个无 UI 依赖的目录/映射组件负责解析、规范化、冲突检测和按手势查找动作。`ShortcutRouter` 只消费该组件并调用现有 ViewModel 命令。
   - 备选方案：继续在 View 中注册多个 `KeyBinding`。放弃原因是无法统一处理动态更新，也难以测试冲突和文本输入焦点边界。

3. **设置文档新增 shortcuts section**
   - 在 `ChapterToolSettings` 增加可选的快捷键覆盖集合；规范化时补齐缺省动作并忽略未知 ID。保存仍由现有聚合 store 一次完成，schema 版本按连续升级规则处理缺少 section 的旧文档。
   - 备选方案：单独 shortcuts.json。放弃原因是违反统一设置文档和一次提交约束。

4. **设置编辑采用录入控件而非自由文本**
   - 快捷键行使用专门的 gesture capture 控件或等效事件适配，将按键事件转换为规范字符串；文本框仅用于显示，不作为解析入口。冲突和保留键校验在草稿层完成。
   - 备选方案：允许用户手写 `Ctrl+...` 文本。放弃原因是格式错误率高，且无法可靠表达平台键名。

5. **Headless 测试覆盖完整工作流**
   - 在现有 Headless 测试集合中打开 `SettingsToolView`，通过 UI 线程录入手势、保存设置，再在主窗口发送该手势并观察目标命令状态/调用记录；同时覆盖冲突、重置和放弃。
   - 备选方案：只测试 ViewModel 属性。放弃原因是无法验证 Tab 可见性、绑定和菜单手势更新。

## Risks / Trade-offs

- [平台键名差异] → 使用 Avalonia `KeyGesture` 的规范解析和显示，不持久化平台特定扫描码；对无法跨平台表示的组合显示校验错误。
- [旧设置兼容] → 缺少 shortcuts section 时注入默认映射，未知动作 ID 在加载时忽略并在保存时不重新生成。
- [动态菜单绑定复杂度] → 将菜单 InputGesture 绑定到可观察的活动映射，并以 Headless 测试验证自定义后即时刷新。
- [命令冲突导致不可达] → 保存前进行全量唯一性检查；冲突时保留上一次有效运行时映射，阻止提交。

## Migration Plan

1. 增加快捷键模型、目录和 `ChapterToolSettings` section，提供从当前默认映射的规范化升级。
2. 改造 `ShortcutRouter`、主窗口菜单/提示和设置 ViewModel/View，接入共享映射和草稿生命周期。
3. 添加非 Headless 的目录/校验测试，再添加 Headless 设置与主窗口工作流测试。
4. 发布后首次加载旧设置时自动补齐 shortcuts 默认值；若保存失败，继续使用此前有效映射。

回滚时可移除快捷键 section 的读取覆盖并恢复目录默认路由；未知 section 字段会被忽略，因此旧版本不会破坏已有设置文件。
